# Optical Ethernet audit (parked)

The attached converter is FS UMC-GA1F1T. The user identified its SFP as Calix 100-05620 rev 10 / ETB43334-7TB4-CA, and noted that it is untested. Calix lists 100-05620 as a 1GE Active Ethernet SC/APC module with a **1310 nm transmitter**: https://www.calix.com/declarations . This is the same transmit direction as the HH4000 GPON path, which receives the 1480-1500 nm downstream band and transmits upstream at 1310 nm (ITU-T G.984.2). A direct Active Ethernet experiment needs a complementary 1490 nm transmitter / 1310 nm receiver at the peer, plus working software. The current SFP is therefore not a matching peer for that path; its operational health was not established.

Read-only stock checks found GBE / EMAC4 / 0101, GPON-selected GPIO60=1, GPIO58=0, XGS RX-disable GPIO32=1. Both optical hwmon devices returned zero receive-power readings. `laser power --rxread` reported -40.000 dBm on M02099; TX was off. LFP on the converter can also suppress transmission, so these readings alone do not identify a failed transceiver. No WAN mode, identity, GPIO or optical calibration setting was changed.

An attempted `serdesctrl --help` revealed that this shell wrapper runs several fallback commands instead of providing a read-only help mode. Their writes failed because /proc/serdes/wan did not exist in GBE/EMAC4 mode; none of those controls ran. Inspect this script before invoking it again.

There is a positive software finding: generic `SERDES_WAN_TYPE_AE` is enum 4 in the matching vendor wan_drv.h. The actual bcm_pondrv.ko jump table maps 4 through pon_drv_epon_init to the same EPON_1_1_params initialization as mode 2. Thus the earlier statement that only faster AE modes were found was incomplete. This establishes a 1G SerDes initialization path statically, not successful Ethernet through the soldered optics. Kernel driver parameters do not expose a simple WAN selector; rdpa_mw latches scratchpad values during insertion. A future experiment should supply the mode in RAM before driver initialization, retaining the existing Ethernet/Wi-Fi image as fallback.

Evidence: `work/pon/live/stock-audit.raw`, `ae-static-parameters.json`, `work/pon/wan-serdes-config.S`, `pon-drv-epon-init.S`. The user asked to park the optical work and prioritize the configurable OpenWrt front panel. No PON flash settings were written.

For future converter tests, the FS guide describes DIP1=LFP, DIP2=ALS, DIP3=FX reset, DIP4=speed (OFF=1000M). All OFF removes automatic link/laser/reset behavior and fixes 1G, but cannot correct wavelengths. Use the printed ON/OFF marking rather than assuming up/down orientation. Official guide: https://img-en.fs.com/file/datasheet/mini-unmanaged-gigabit-ethernet-media-converters-quick-start-guide-v3.0.pdf .
